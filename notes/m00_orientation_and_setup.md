## What I built

`setup.sh`, which rebuilds the lab from nothing and is safe to re-run. It
creates the virtualenv, clones jaffle shop at the pinned commit, runs
`dbt build` into a local DuckDB file, runs `dct init`, registers the dbt
profile as a source named `jaffle`, writes `source: jaffle` into
`charts/meta.yml`, and links `boards/` into the lab as `charts/lessons/`.

What `dct init` leaves behind, and what each piece is for:

- `dbt_charts.yml` at the project root — the anchor. It holds the `sources:`
  registry, the set of named connections a board may read from, and dct walks
  up from the working directory to find it.
- `charts/` — boards live here; drop a `.yml` in and `dct serve` picks it up.
- `charts/meta.yml` — directory-level defaults a board inherits when it does
  not set them itself.

The pipeline, as the post ended up drawing it: `dbt build` produces models and
the manifest; the board YAML references them with `{{ ref() }}`; `dct validate`
checks schema and refs against the manifest with no database connection;
`dct render` runs the SQL, compiles to Vega-Lite and writes HTML, PNG, SVG or
PDF. dct models nothing and materialises nothing — it replaces the dashboard
layer only.

## Errors and warnings (verbatim)

No transcript was captured for this module. One failure is recorded in prose,
in `setup.sh` and `TROUBLESHOOTING.md`:

```
ParseError: Empty YAML document
```

raised from `_charts_meta_default_source`. `dct init` scaffolds `charts/meta.yml`
as comments only, a comments-only file parses to nothing, and 0.8.0 has no
guard for that, so every render in the project dies. Writing one real key
clears it. The message above is quoted from those notes, not from a captured
run — worth reproducing and capturing properly before it is used in a post,
since it is an unhandled crash with no error code on a file the tool generated
itself.

Environment problems from this module — PowerShell activation, CRLF in
`setup.sh`, a global dbt shadowing the pinned jaffle shop — are in
`TROUBLESHOOTING.md` by design and deliberately not repeated here.

## What surprised me

- dct variables are written `{{ region }}`, not dbt's `{{ var('region') }}`.
  Same braces, different rules: a board file looks like dbt YAML and is not
  dbt YAML. Not yet tried on a real board.
- On a KPI card the number updates with the data and the colour does not. The
  glyph and the tone are static fields you type in, so a card stays green with
  an up-arrow after its number goes negative. The published `kpi-overview`
  example reads as correct only because its data never changes.
- The tool's own scaffolding breaks the tool: the `meta.yml` that `dct init`
  writes fails every render until you edit it.
